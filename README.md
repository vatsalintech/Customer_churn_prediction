# ChurnScope — Customer Churn Prediction

A machine learning project that predicts whether a telecom customer is likely to cancel their service, and turns that prediction into something a business team can actually use through an interactive dashboard.

**Live demo:** https://churnscope-customerintelligence.streamlit.app/

---

## The Problem

Customer churn is expensive. Acquiring a new customer usually costs more than keeping an existing one, so companies want to spot at-risk customers early and intervene before they leave.

This project tackles that problem using historical telecom customer data. The goal is not just to build a model with good accuracy on paper, but to **catch as many real churners as possible** — even if that means flagging a few extra customers who would have stayed. Missing someone who is about to leave is usually worse than offering a retention deal to someone who was not going to churn anyway.

---

## Solution

The project has two main parts:

### 1. Analysis & model training (`customer_churn_prediction.ipynb`)

An end-to-end notebook that walks through:

- **Exploratory data analysis (EDA)** on 7,043 customer records
- **Data cleaning** — fixing missing `TotalCharges` values for new customers
- **Feature engineering** — adding `avg_monthly_spend`, `has_internet`, and `long_term_contract`
- **Model training** — Logistic Regression with balanced class weights
- **Evaluation** — ROC AUC, precision-recall curves, and threshold tuning
- **Model export** — saving the trained pipeline to `churn_model_artifacts.joblib`

### 2. Interactive dashboard (`app.py`)

A Streamlit app called **ChurnScope** that lets you enter a customer profile and instantly see:

- Churn probability
- A clear "likely to churn" or "likely to stay" label
- Estimated customer lifetime value (LTV)
- Simple retention suggestions for high-risk customers

The dashboard only asks for the six inputs that matter most in practice. Other fields (gender, partner status, add-on services, etc.) are filled with sensible defaults behind the scenes so the form stays short and usable.

---

## Key Findings from the Data

Before building the model, the data told a clear story:

| Insight | Detail |
|---|---|
| Overall churn rate | ~26.5% of customers churned |
| Class imbalance | ~74% stayed, ~27% left — handled with stratified splits and balanced weights |
| High-risk signals | Month-to-month contracts, fiber optic internet, electronic check payments, low tenure |
| Protective signals | Longer contracts (1–2 years), higher tenure, no internet service |
| Data quality | 11 rows had missing `TotalCharges` (new customers with tenure = 0) |

The strongest predictors in the final model were **tenure**, **monthly charges**, **internet service type**, and **contract length**.

---

## Model Results

The model was evaluated on a held-out 20% test set (stratified to preserve the churn rate).

| Metric | Value |
|---|---|
| **ROC AUC** | 0.841 |
| **Average Precision** | 0.632 |
| **Optimal threshold** | 0.40 |
| **Recall (churn detected)** | 86.6% |
| **Precision** | 46.6% |
| **F1 Score** | 0.606 |

**What this means in practice:** At the chosen threshold, the model catches about **87 out of every 100 customers who actually churn**. Roughly half of everyone flagged as "at risk" truly would have left — the rest are false alarms that a retention team could follow up on anyway.

The reason to tune threshold for high recall rather than perfect precision was intentional, because the business cost of missing a churner is higher than the cost of an unnecessary retention offer.

## Getting Started

### Prerequisites

- Python 3.9 or newer
- `pip`

### 1. Clone and set up the environment

```bash
git clone https://github.com/vatsalintech/Customer_churn_prediction.git
cd "Customer churn prediction"

python -m venv .venv
source .venv/bin/activate        # On Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

### 2. Train the model (first time only)

Open and run all cells in `customer_churn_prediction.ipynb`:

```bash
jupyter notebook customer_churn_prediction.ipynb
```

The last section saves `churn_model_artifacts.joblib`, which the dashboard needs. You only need to re-run this if you change the model or retrain on new data.

### 3. Run the dashboard

```bash
streamlit run app.py
```

Streamlit will print a local URL (usually `http://localhost:8501`). Open it in your browser.

## Using the Dashboard

1. **Prefill examples** — Click "High-risk customer" or "Loyal customer" to load sample profiles and see how the model behaves on obvious cases.
2. **Enter a profile** — Adjust the six fields in the form:
   - Internet plan (Fiber optic / DSL / No)
   - Tenure in months (0–72)
   - Contract type (Month-to-month / One year / Two year)
   - Monthly bill ($18–$120)
   - Payment method
   - Multiple phone lines (Yes / No)
3. **Click Predict** — The results panel shows:
   - Churn probability as a percentage and progress bar
   - Estimated lifetime value (LTV)
   - Amount billed to date
   - Expected future months of revenue
   - A short retention suggestion for at-risk customers

### Example profiles

| Profile | Internet | Tenure | Contract | Monthly bill | Payment | Lines | Typical outcome |
|---|---|---|---|---|---|---|---|
| High-risk | Fiber optic | 1 mo | Month-to-month | $30 | Electronic check | Yes | Likely to churn |
| Loyal | No internet | 72 mo | Two year | $70 | Bank transfer | No | Likely to stay |

### How LTV is estimated

The dashboard calculates a simple LTV estimate:

```
LTV = billed to date + (monthly charges × expected future months)
```

Expected future months depend on the contract type and are reduced by the churn probability.

## Limitations & Notes

- The model was trained on historical telecom data. Results may not transfer directly to a different industry or customer base without retraining.
- The dashboard uses default values for fields not shown in the form. Predictions are most reliable when those defaults are close to your typical customer.
- Precision is intentionally traded for recall. Expect some false positives when acting on predictions.
